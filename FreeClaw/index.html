Features

Everything you need.
Nothing you don't.

FreeClaw classifies your intent locally before touching any API, then decides how much history to send, how cold to run, and which tools to offer — per message.

🌐
Web Search & Scraping
Pulls instant answers, news, and snippets from DuckDuckGo, then scrapes and cleans the top result pages — all stitched into one structured block. No extra model call spent summarizing.
🧠
Memory That Pages In
Durable facts live in context.md under headers. Each turn carries only the About and Preferences sections plus the names of the rest — the agent pulls a section in with search_context when the conversation needs it, so memory can grow for years without growing the prompt.
🛡️
Approval-Gated Bash
The agent can run shell commands — but only ones you've explicitly approved. You see the exact command; nothing runs on a non-answer. The gate lives outside the model entirely.
🧩
MCP Servers — HTTP & stdio
Connect external Model Context Protocol servers over HTTP, or run them as local stdio processes — the transport most published servers actually ship. Tools merge into the agent's toolset automatically, no restart required.
💾
Prompt Caching
The system prompt is laid out stable-part-first so providers serve the repeated prefix from cache at a discount. Providers that need an explicit breakpoint (Anthropic, Gemini, Qwen) get one automatically — nothing to configure.
🔢
Exact Token Counts
Every request asks the provider for its real usage numbers. The counter shows exact figures where available, a clearly-marked estimate where not — hover for tokens in, out, cached, and requests per turn.
⚡
Adaptive Turns
Classy-AI tags your message locally before any API call, and the tag sets the turn: how much history goes out, the sampling temperature, and which tools are offered. Small talk gets a tiny window and no tools.
🔀
Multi-Provider Fallback
Add any OpenAI-compatible endpoint from Settings → Providers — URL, key, model. The agent tries them in order and falls through to the next on errors or rate limits. No keys are collected at install.
📄
Files, Pages & Vision
Creates, reads, edits, and manages files in its sandboxed static folder; publishes live HTML pages at a shareable URL; describes uploaded images in detail using a vision model you pick.
👥
Multi-User
Each user gets their own folder, conversation history, long-term memory, and bash approval rules. Approving a command as one user grants nothing to anyone else.
🖥️
Terminal CLI
Run freeclaw for the same agent in your terminal — same tools, same memory, live streaming, and a per-turn summary line with real token counts.
🔌
OpenAI-Compatible API
A stateful /v1/chat/completions endpoint on the same port. Any OpenAI client drives the same conversation the web UI shows — send one message, the server supplies the history.
How It Works

From your browser
to the model.

Every message passes through a cost-optimization layer before a single token reaches your provider.

01
You sign in and type
FreeClaw runs a local Flask server on port 6767, behind a password login. Chat from any browser on your network — or from the freeclaw CLI in your terminal.
02
Local intent classification
Before any API call, Classy-AI reads your message locally and tags the intent — greeting, banter, search, logic, math, coding, editing — then picks the context window, temperature, and toolset for that turn. Zero tokens spent.
03
Provider call with trimmed, cacheable context
Only the relevant recent messages go out to the first enabled provider in Settings → Providers, prefixed by a system prompt laid out so the provider can serve it from cache. If a provider errors out or rate-limits, FreeClaw falls through to the next one in your list automatically.
04
Tool execution — with a gate on bash
If the model calls a tool — web search, file and page management, memory, vision, or anything from a connected MCP server — FreeClaw executes it locally and feeds the result back. A bash command pauses the turn until you approve it (or it matches a rule you saved earlier); a refusal or timeout means it never runs.
05
Response streamed back, usage counted
The reply streams to your browser as server-sent events, rendered with full markdown. The token counter shows the provider's exact usage — sent, received, and served-from-cache — for the whole turn, tool round-trips included.
Cost Philosophy

Engineered to cost
almost nothing.

One principle: use the cheapest path that can do the job. FreeClaw stacks these strategies on every single message, and the result is a capable agent that runs all day for fractions of a cent.

Strategy 01
Zero-token routing
100% local · 0 tokens

Intent classification runs entirely on your machine with a local PyTorch model. Routing decisions — window size, temperature, toolset — cost no API call, no tokens, no latency.

Strategy 02
No tools for small talk
greeting · banter · about-user

Conversational intents are sent with no tool definitions at all and a minimal message window. Tool schemas are only paid for when the task actually calls for them.

Strategy 03
Trimmed context windows
a handful of messages, not the history

The number of past messages sent per turn scales with the intent's complexity. A greeting sends a few recent messages; coding sends more. Full history is never blindly replayed.

Strategy 04
Prompt caching, automatically
stable prefix · cache_control where needed

The system prompt's fixed part comes first, so providers that cache automatically just work. Models that need an explicit breakpoint (Anthropic, Gemini, Qwen) get cache_control attached — and cache reads show up in your token counter.

Strategy 05
Memory, not replay
context.md · paged in on demand

Long-term facts are written once under headers in context.md. Only two sections plus the other headers' names ride along each turn; the rest is fetched only when a conversation actually needs it.

Strategy 06
No LLM call for search
DuckDuckGo + BeautifulSoup

Search results are gathered, freshness-filtered, scraped, and structured entirely with deterministic code — capped at 2 searches per task, and never a separate model call to summarize.

You're In Control

Your machine.
Your rules.

An agent with shell access should have to ask. FreeClaw's guardrails live outside the model — the LLM can't grant itself anything, and can't talk its way past a gate.

🛡️ Bash approvals, outside the model

Every shell command pauses the agent's turn and shows you the exact command. The model is never asked and can't answer — the prompt is raised by FreeClaw itself. Ignoring it, closing the tab, or letting it time out all count as refusals.

"Always allow" saves a rule per user, and compound commands (;, &&, pipes, redirects) can never match a saved rule — ls; rm -rf ~ doesn't get to hide behind a rule that says ls.

🔒 Self-hosted, password-protected

FreeClaw runs on your hardware and answers only to you. The web UI sits behind a login screen, so it's safe to leave reachable on your local network — and the API authenticates with the same password as a Bearer token.

Your conversations, memory, and files live in the install directory on your disk. No account, no cloud dependency, no vendor in the loop.

📡 Telemetry: off by default

The installer asks once, and the default answer is no. If you opt in, FreeClaw sends exactly one request, ever: install id, version, OS, and install method. Four fields, no IP logging, nothing else — the receiving schema has no column for anything else.

It exists to answer one question — how many people installed this — and the ~100 lines of code that send it are right there to read.

📖 Open source, debuggable

MIT-licensed, front to back. Every unexpected failure — a provider erroring, a tool crashing, an MCP server going unreachable — lands with its full traceback in logs/freeclaw.log, so the real cause is never hidden behind a short error bubble.

Updates are one script — ./update.sh or ./update-mac.sh — and they never touch your data.

OpenAI-Compatible API

Any client.
Same agent.

Toggle /v1/chat/completions on the same port with the API chip on the homepage or /startapi in chat, and any OpenAI SDK or client can drive your agent — it's a full agent turn, not a raw model call. Tools run, search fires, memory is read and written.

model picks the user, not the model

Which LLM answers is FreeClaw's business. What you're choosing is whose memory, conversation, and approval rules the turn runs against — and GET /v1/models lists your users, so any client's model dropdown becomes a user picker for free.

History lives on the server

Send one message; FreeClaw supplies everything before it and appends the turn. It's the same thread the chat page shows — send a message here and it's there when you open the browser, and vice versa.

Streaming & real usage

Set "stream": true for streamed text while tool calls run transparently. The usage block carries the provider's own token counts for the whole turn, tool round-trips included.

Safe with nobody watching

On an API turn there's no one to answer a bash approval prompt, so a command runs only if it matches a saved always-allow rule. Anything else is refused rather than left hanging.

python 
# pip install openai — nothing FreeClaw-specific needed
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:6767/v1",
    api_key="YOUR_FC_PASSWORD",
)

client.chat.completions.create(
    model="Elliot",  # a FreeClaw user, not an LLM
    messages=[{"role": "user",
               "content": "what did I say my cat was called?"}],
)

Installation

One command.
You're done.

The installer handles everything. On Linux it runs natively under systemd; on macOS it runs in Docker. Pick your platform below.

terminal
$ curl -fsSL https://freeclaw.eedeb.dev/install.sh | bash
🐧 Linux requires git, python3, sudo
$ curl -fsSL https://freeclaw.eedeb.dev/install-mac.sh | bash
🍎 macOS requires git and Docker Desktop (running)
1
Clone & set up environment
The script clones the repo and installs every dependency — PyTorch (CPU), Flask, the OpenAI SDK, and the Classy classifier. On Linux that goes into a Python virtual environment; on macOS it's built into a Docker image instead. Either way you only get the files for your own platform.
2
Set a password for the web UI
FreeClaw's chat UI sits behind a login screen. You'll set a password during install so it's safe to leave running on your network. That's the only thing collected here — no API keys. It's written to a local .env file, never committed anywhere.
3
FreeClaw starts automatically
On Linux the installer registers a systemd service so FreeClaw starts on boot; on macOS the container restarts itself with Docker. Both install the freeclaw terminal client and print the local URL — http://localhost:6767 on macOS, something like http://192.168.x.x:6767 on Linux.
4
Add a provider in the web UI
Open the URL, sign in, and head to Settings → Providers. Add any OpenAI-compatible endpoint — URL, API key, model name — and stack as many as you like for fallback. FreeClaw can't answer until at least one is configured. Optionally add MCP servers under Settings → MCP Servers while you're there.
5
Start chatting
Chat from any browser on your network, or run freeclaw for the same agent in your terminal. Later on, ./update.sh on Linux (or ./update-mac.sh on macOS) pulls the latest changes and restarts FreeClaw, leaving your data alone.
