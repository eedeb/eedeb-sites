Every message is routed, trimmed, and cached before it costs anything. Search is free, classification is local, and the repeated prompt prefix is served from the provider's cache — not your wallet.

Capabilities

A complete agent.
Engineered frugally.

FreeClaw classifies your intent locally before touching any API, then decides how much history to send, how cold to run, and which tools to offer — per message.

Web search & scraping

Instant answers, news, and snippets from DuckDuckGo, plus the top result pages scraped and cleaned — stitched into one structured block with no extra model call spent summarizing.

Memory that pages in

Facts live in context.md under headers. Each turn carries two key sections plus the names of the rest; the agent pulls a section in only when the conversation needs it. Memory grows for years — the prompt doesn't.

Approval-gated shell

The agent can run bash — but only commands you've explicitly approved. You see the exact command; nothing runs on a non-answer; the gate lives outside the model entirely.

MCP servers, HTTP & stdio

Connect Model Context Protocol servers over HTTP or run them as local stdio processes — the transport most published servers ship. Tools merge in automatically, no restart.

Prompt caching, automatic

The system prompt is laid out stable-part-first so providers serve the repeated prefix from cache at a discount. Models that need an explicit breakpoint (Anthropic, Gemini, Qwen) get one — nothing to configure.

Exact token accounting

Every request asks the provider for its real usage. The counter shows exact figures where available, a clearly-marked estimate where not — with tokens in, out, cached, and requests per turn on hover.

Adaptive turns

Classy-AI tags each message locally, and the tag sets the turn: history window, sampling temperature, and toolset. Small talk gets a tiny window and no tools; precision work runs colder with everything.

Multi-provider fallback

Add any OpenAI-compatible endpoint from Settings → Providers. The agent tries them in order and falls through on errors or rate limits. No keys are collected at install.

Files, pages & vision

Creates, reads, and edits files in its sandboxed folder; publishes live HTML pages at a shareable URL; describes uploaded images using a vision model you pick.

Multi-user by default

Each user gets their own folder, history, long-term memory, and approval rules. Approving a command as one user grants nothing to anyone else.

Terminal CLI

Run freeclaw for the same agent in your terminal — same tools, same memory, live streaming, and a per-turn summary line with real token counts.

OpenAI-compatible API

A stateful /v1/chat/completions endpoint on the same port. Any OpenAI client drives the same conversation the web UI shows — send one message, the server supplies the history.

Under the hood

Every token, accounted for.

Each message passes through a cost-optimization pipeline before a single token reaches your provider.

1

Sign in and type

FreeClaw runs a local Flask server on port 6767, behind a password login. Chat from any browser on your network — or from the freeclaw CLI in your terminal.

2

Local intent classification

Before any API call, Classy-AI reads your message locally and tags the intent — greeting, banter, search, logic, math, coding, editing — then picks the context window, temperature, and toolset for that turn. Zero tokens spent.

3

Provider call with trimmed, cacheable context

Only the relevant recent messages go out to your first enabled provider, prefixed by a system prompt laid out so it can be served from cache. If a provider errors or rate-limits, FreeClaw falls through to the next in your list automatically.

4

Tool execution — with a gate on the shell

Web search, files, pages, memory, vision, or anything from a connected MCP server executes locally and feeds back into the turn. A bash command pauses everything until you approve it — or it matches a rule you saved earlier. A refusal or timeout means it never runs.

5

Streamed response, real usage

The reply streams back as server-sent events with full markdown rendering. The token counter shows the provider's exact usage — sent, received, and served-from-cache — for the whole turn, tool round-trips included.

Cost engineering

Six ways your bill
stays near zero.

One principle: use the cheapest path that can do the job. These strategies stack on every single message.

No. 1

Zero-token routing

Intent classification runs entirely on your machine with a local PyTorch model. Routing decisions — window size, temperature, toolset — cost no API call, no tokens, no latency.

No. 2

No tools for small talk

Conversational intents are sent with no tool definitions and a minimal message window. Tool schemas are only paid for when the task actually calls for them.

No. 3

Trimmed context windows

The number of past messages sent per turn scales with the intent's complexity. A greeting sends a few; coding sends more. Full history is never blindly replayed.

No. 4

Automatic prompt caching

The prompt's fixed part comes first, so providers that cache automatically just work — and models that need an explicit breakpoint get cache_control attached. Cache reads show up in your token counter.

No. 5

Memory, not replay

Long-term facts are written once under headers in context.md. Only two sections plus the other headers' names ride along each turn; the rest is fetched on demand.

No. 6

No LLM call for search

Results are gathered, freshness-filtered, scraped, and structured entirely with deterministic code — capped at two searches per task, never a separate model call to summarize.

Security & control

Your machine.
Your rules.

An agent with shell access should have to ask. FreeClaw's guardrails live outside the model — the LLM can't grant itself anything, and can't talk its way past a gate.

Shell approvals, outside the model

Every command pauses the agent's turn and shows you exactly what it wants to run. The model is never asked and can't answer — the prompt is raised by FreeClaw itself. Ignoring it, closing the tab, or letting it time out all count as refusals.

"Always allow" saves a rule per user — and compound commands (;, &&, pipes, redirects) can never match a saved rule, so ls; rm -rf ~ can't hide behind a rule that says ls.

Self-hosted & password-protected

FreeClaw runs on your hardware and answers only to you. The web UI sits behind a login screen, so it's safe to leave reachable on your local network — and the API authenticates with the same password as a Bearer token.

Your conversations, memory, and files live in the install directory on your disk. No account, no cloud dependency, no vendor in the loop.

Telemetry: off by default

The installer asks once; the default answer is no. If you opt in, FreeClaw sends exactly one request, ever: install id, version, OS, install method. Four fields, no IP logging — the receiving schema has no column for anything else.

The ~100 lines of code that send it are right there to read.

Open source & debuggable

MIT-licensed, front to back. Every unexpected failure — a provider erroring, a tool crashing, an MCP server going unreachable — lands with its full traceback in logs/freeclaw.log, so the real cause is never hidden behind a short error bubble.

Updates are one script — ./update.sh or ./update-mac.sh — and they never touch your data.

Integrate

Any OpenAI client.
Same agent.

Toggle /v1/chat/completions on the same port with the API chip on the homepage or /startapi in chat. It's a full agent turn, not a raw model call — tools run, search fires, memory is read and written.

model picks the user, not the model

Which LLM answers is FreeClaw's business. You're choosing whose memory, conversation, and approval rules the turn runs against — and GET /v1/models lists your users, so any client's model dropdown becomes a user picker for free.

History lives on the server

Send one message; FreeClaw supplies everything before it and appends the turn. It's the same thread the chat page shows — send a message here and it's there when you open the browser.

Streaming & real usage

Set "stream": true for streamed text while tool calls run transparently. The usage block carries the provider's own token counts for the whole turn, tool round-trips included.

Safe with nobody watching

On an API turn there's no one to answer an approval prompt, so a shell command runs only if it matches a saved always-allow rule. Anything else is refused rather than left hanging.

quickstart.py python 
# pip install openai — nothing FreeClaw-specific needed
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:6767/v1",
    api_key="YOUR_FC_PASSWORD",
)

client.chat.completions.create(
    model="Elliot",  # a FreeClaw user, not an LLM
    messages=[{
        "role": "user",
        "content": "what did I say my cat was called?",
    }],
)

Installation

One command.
You're done.

The installer handles everything. On Linux it runs natively under systemd; on macOS it runs in Docker; on Windows it runs inside WSL using the Linux installer.

terminal
$curl -fsSL https://freeclaw.eedeb.dev/install.sh | bash
runs natively under systemd · requires git, python3, sudo

Clone & set up the environment

The script clones the repo and installs every dependency — PyTorch (CPU), Flask, the OpenAI SDK, and the Classy classifier. Linux gets a Python virtual environment; macOS gets a Docker image. Either way, only your platform's files are checked out.

Set a password

FreeClaw's chat UI sits behind a login screen, so it's safe to leave running on your network. The password is the only thing collected — no API keys — and it's written to a local .env file, never committed anywhere.

FreeClaw starts automatically

Linux registers a systemd service that starts on boot; macOS runs the container with a restart policy. Both install the freeclaw terminal client and print your local URL — http://localhost:6767 on macOS, something like http://192.168.x.x:6767 on Linux.

Add a provider

Open the URL, sign in, and head to Settings → Providers. Add any OpenAI-compatible endpoint — URL, API key, model — and stack as many as you like for fallback. Optionally connect MCP servers while you're there.

Start chatting

Chat from any browser on your network, or run freeclaw in your terminal. Later, ./update.sh (or ./update-mac.sh) pulls the latest changes and restarts FreeClaw, leaving your data alone.
